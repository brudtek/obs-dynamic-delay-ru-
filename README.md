# Управление задержкой для OBS — русская упрощённая сборка

Плагин для OBS Studio 32.2 (Windows x64). Включает и снимает задержку трансляции
и записи прямо во время эфира, не останавливая поток. Пока набирается задержка,
зрители видят выбранную сцену ожидания. При снятии задержки поток сразу
переходит на текущую живую картинку, накопленное видео пропускается.

Это доработанная версия плагина **OBS Dynamic Delay 1.2.0** (автор — Aritz,
[stanixdor/obs-variable-delay](https://github.com/stanixdor/obs-variable-delay),
тег `1.2.0`, коммит `8075c33`). Изменения:

- весь интерфейс, состояния, подсказки и сообщения об ошибках переведены на русский;
- удалён мультистрим: отдельная панель, список площадок, ввод серверов и ключей,
  собственный RTMP-клиент и всё, что обслуживало только его;
- панель приспособлена к узкой ширине и крупному масштабу Windows;
- приглушённые пояснения стали читаемыми на тёмной теме.

Механизм задержки, сцена ожидания, звук сцены ожидания, предпросмотр и
сохранение настроек остались прежними.

## Что умеет панель «Управление задержкой»

| Элемент | Назначение |
|---|---|
| Состояние | «Прямой эфир», «Подготовка», «Накопление задержки», «Эфир с задержкой», «Переход в прямой эфир», «Ошибка — прямой эфир» |
| Задержка | Ползунок и число справа, от 1 до 300 секунд |
| Сцена ожидания | Что видят зрители, пока набирается задержка |
| Способ перехода | «По ключевому кадру». «Затемнение» требует перекодирования и, как в исходном плагине, недоступно |
| Звук сцены ожидания | Звук сцены, отдельный источник, резервная дорожка OBS или тишина |
| Память | Ожидаемый расход памяти при выбранной задержке и текущий размер буфера |
| Кнопка | «Включить задержку», «Отменить накопление», «Снять задержку», «Отменить включение задержки» — по состоянию |
| Предпросмотр выходящего потока | Раскрывается под кнопкой, показывает примерно то, что OBS отправляет зрителям |

## Сборка

Нужны Visual Studio 2022 Build Tools (C++), CMake 3.28+ и доступ к GitHub
для загрузки исходников OBS 32.2.2 и пакетов obs-deps / Qt6 (адреса и
SHA-256 зафиксированы в `buildspec.json`).

```powershell
cmake --preset windows-x64 -DENABLE_TESTS=ON
cmake --build build_x64 --config RelWithDebInfo
ctest --test-dir build_x64 -C RelWithDebInfo
powershell -ExecutionPolicy Bypass -File scripts\package-windows.ps1
```

Готовый архив появится в `release\`.
